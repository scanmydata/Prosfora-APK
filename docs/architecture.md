# Αρχιτεκτονική — αναθεωρημένη (21/8/2026)

Το αρχικό πλάνο έλεγε Firebase (Firestore + Auth + Cloud Functions). **Με βάση τις απαιτήσεις σου, το Firebase φεύγει εντελώς.** Οι απαιτήσεις ήταν:

1. Το PDF template να παραμείνει **επεξεργάσιμο από το Google Drive**, όπως τώρα
2. **Backup στο Google Drive**, εύκολο και καθαρό
3. **Ευκολότερη εισαγωγή σημειώσεων**
4. Email μέσω **SMTP**
5. **Updates από GitHub Releases**

Καμία από αυτές δεν χρειάζεται Firebase. Το Firestore θα ήταν δεύτερο cloud δίπλα στο Drive, και οι Cloud Functions θα ήταν server μόνο και μόνο για να στείλει ένα email που το SMTP το στέλνει κατευθείαν. **Χωρίς backend = μηδέν κόστος, μηδέν συντήρηση.**

## Νέο στοίβαγμα

| Στοιχείο | Υλοποίηση |
|---|---|
| UI | Kotlin + Jetpack Compose (Material 3) |
| Βάση | **Room / SQLite τοπικά** — offline-first, ό,τι πιο γρήγορο |
| Backup / restore | **Google Drive API** — αυτόματο backup της βάσης + χειροκίνητο restore |
| PDF | **Google Docs API** πάνω στο υπάρχον template — μένει επεξεργάσιμο από το Drive |
| Email | **SMTP** (Jakarta/JavaMail) απευθείας από τη συσκευή |
| Updates | **GitHub Releases API** — έλεγχος, download, install μέσα από το app |
| Auth | Google Sign-In **μόνο** για τα Drive/Docs scopes (όχι για login στο app) |

Το app ανοίγει και δουλεύει χωρίς internet. Το δίκτυο χρειάζεται μόνο για PDF, email, backup, update.

## Πώς λύνεται το «template επεξεργάσιμο από το Drive»

Το AppSheet έκανε *MakeDoc*: έπαιρνε το Google Doc, αντικαθιστούσε τα `<<[Στήλη]>>`, έβγαζε PDF. Το ίδιο ακριβώς κάνουμε με το Docs API:

```
1. drive.files.copy(templateId)              → προσωρινό αντίγραφο
2. docs.documents.batchUpdate(copyId)        → replaceAllText για τα απλά πεδία
                                               insertTableRow + κείμενο για τους χώρους
                                               bullets για τις παρατηρήσεις
3. drive.files.export(copyId, "application/pdf")
4. drive.files.delete(copyId)                → καθαρό Drive
```

Template: `1hgWNL034KwLS9RiaMiQ7pXQXB1bhaKcSsUtQGqZKDF4` — **δεν το αγγίζουμε ποτέ**. Αλλάζεις λογότυπο, κείμενα, δείγματα εργασιών κατευθείαν στο Google Docs και το επόμενο PDF βγαίνει με τις αλλαγές. Ακριβώς όπως τώρα.

### Placeholders του template
| Placeholder | Πηγή |
|---|---|
| `<<[Είδος]>>` | Προσφορά → Είδος (χωρίς τη λέξη «χρωματισμός») |
| `<<[Οδός / Περιοχή]>>` | Προσφορά → Οδός / Περιοχή, με κεφαλαία (και στο filename & subject) |
| `<<[Ημερομηνία]>>` | Προσφορά → Ημερομηνία (μορφή `d/M/yyyy`) |
| `<<[Ισχύει έως]>>` | Προσφορά → Ισχύς· `—` αν δεν έχει οριστεί |
| `<<Start:[Χώροι]>> … <<End>>` | επανάληψη γραμμής πίνακα ανά χώρο |
| `<<[Περιγραφή Χώρου]>>` `<<[Επιφάνεια (τ.μ.)]>>` `<<[Τιμή Μονάδος]>>` `<<[Σύνολο Γραμμής]>>` | στήλες χώρου |
| `<<[Γενικό Σύνολο Live]>>` | το ποσό που πληρώνει ο πελάτης — με ΦΠΑ όταν υπάρχει (μορφή `1.892,99 €`) |
| `<<[Καθαρή Αξία]>>` | άθροισμα γραμμών, χωρίς ΦΠΑ |
| `<<[ΦΠΑ]>>` | ο ΦΠΑ σε ευρώ |
| `<<[Αν ΦΠΑ]>>` | δείκτης: η γραμμή πίνακα (ή η παράγραφος) που τον περιέχει σβήνεται όταν η προσφορά δεν έχει ΦΠΑ |
| `<<[Παρατηρήσεις]>>` | η παράγραφος επαναλαμβάνεται μία φορά ανά σημείωση |
| `<<[Τρόπος Πληρωμής]>>` | η παράγραφος επαναλαμβάνεται μία φορά ανά δόση |

Ο παλιός συνδυασμός `<<Start:[Related Ανάλυση_Χώρων]>>` και `<<Start: SELECT(…)>>` / `• <<[Κείμενο]>>` / `<<End>>` εξακολουθεί να υποστηρίζεται, ώστε να δουλεύει και το πρότυπο που ήρθε από το AppSheet.

Στο υποσέλιδο κάθε σελίδας μπαίνει «Σελίδα X από Y» (πεδία `PAGE` / `NUMPAGES`). Από τη 2η σελίδα και μετά μια κενή κεφαλίδα κρατά το κείμενο μακριά από το πάνω χείλος — τα περιθώρια είναι ίδια σε όλες τις σελίδες, οπότε ο αέρας δεν γίνεται αλλιώς.

Ο συντελεστής ΦΠΑ είναι πάντα 24% και δεν ρυθμίζεται: για ελαιοχρωματισμούς δεν υπάρχει μειωμένος, οπότε ένα πεδίο «ποσοστό» θα ήταν μόνο ευκαιρία για λάθος. Τα στατιστικά μετράνε **καθαρή αξία** — ο ΦΠΑ δεν είναι έσοδο.

Το εργοστασιακό πρότυπο παράγεται από το `migration/make_template.py` και ελέγχεται με το `migration/render_template.py` (ίδια λογική με το `DocxTemplate.kt`, σε Python). Χωράει σε μία σελίδα A4 όσο το επιτρέπουν οι γραμμές: παρατηρήσεις και τρόπος πληρωμής μπαίνουν δίπλα-δίπλα.

## Ευκολότερη εισαγωγή σημειώσεων

Σήμερα κάθε σημείωση είναι ξεχωριστή εγγραφή σε άλλο πίνακα, με φόρμα και save. Στο δείγμα PDF φαίνονται 4 σημειώσεις που επαναλαμβάνονται σχεδόν πάντα:

- Στην προσφορά δεν περιλαμβάνεται ο ΦΠΑ τιμολογίου.
- Η προσφορά περιλαμβάνει την εργασία και τα υλικά.
- Τα χρώματα που θα χρησιμοποιηθούν εσωτερικά θα είναι άοσμα πλαστικά της vivechrom.
- Τα δάπεδα θα καλυφθούν με χαρτόνι και τα σοβατεπιά με χαρτοταινία.

**Νέα σχεδίαση**: βιβλιοθήκη έτοιμων σημειώσεων. Στην οθόνη της προσφοράς βλέπεις τις σημειώσεις ως checkbox chips — τσεκάρεις όσες ισχύουν, με ένα tap. Από κάτω πεδίο για ελεύθερο κείμενο, και ό,τι γράψεις μπορείς να το «καρφιτσώσεις» ώστε να εμφανίζεται ως έτοιμη επιλογή στις επόμενες προσφορές. Drag για σειρά.

Αν κάποτε το app πάει σε πολλούς χρήστες, τότε το SMTP πρέπει να μετακομίσει πίσω από server. Για Gmail χρειάζεται **App Password** (με 2FA ενεργό) — όχι ο κανονικός κωδικός.

## Εισαγωγή ιστορικού

Οι παλιές προσφορές είναι ~600 αρχεία `.xls` του Excel 97 (BIFF) σε φακέλους ανά έτος και ανά πελάτη. Το Android δεν διαβάζει BIFF χωρίς ολόκληρο το Apache POI — δεκάδες MB για μια δουλειά που γίνεται μία φορά — οπότε η μετατροπή γίνεται στον υπολογιστή:

```
python migration/import_history.py --folder "…/ΕΠΙΜΕΤΡΗΣΕΙΣ ΔΟΥΛΕΙΕΣ"     --out ιστορικό.json --report παραλείψεις.txt
```

Το script αναγνωρίζει τον πίνακα από την επικεφαλίδα «ΠΕΡΙΓΡΑΦΗ ΧΩΡΟΥ / ΕΠΙΦΑΝΕΙΑ …» (σε όλες τις παραλλαγές που εμφανίζονται), βγάζει είδος και διεύθυνση από το μπλοκ του τίτλου, και διαβάζει τα μπλοκ «ΠΑΡΑΤΗΡΗΣΕΙΣ» και «ΤΡΟΠΟΣ ΠΛΗΡΩΜΗΣ». Η γραμμή «Η προσφορά ισχύει έως …» γίνεται πεδίο αντί για σημείωση.

Η κατάσταση μαντεύεται από τους φακέλους: `DONE` → Ολοκληρώθηκε, `ΠΡΟΣΦΟΡΕΣ` → Σε επεξεργασία, αλλού → Ολοκληρώθηκε.

### Αναγνωριστικά

Τα IDs είναι `hist-` + sha1 **της διαδρομής** του αρχείου μέσα στον φάκελο. Τα φύλλα δεν μετακομίζουν: δουλεύονται εκεί που είναι και τα καινούρια μπαίνουν στον φάκελο της χρονιάς. Άρα η διαδρομή είναι το σταθερό στοιχείο, ενώ το περιεχόμενο αλλάζει — id βασισμένο στο περιεχόμενο θα έφτιαχνε νέα προσφορά κάθε φορά που διορθώνεται μια διεύθυνση.

Δεν γίνεται ένωση διπλότυπων. Δύο αρχεία με ίδιο περιεχόμενο είναι σχεδόν πάντα αντίγραφο της προηγούμενης προσφοράς που δεν συμπληρώθηκε ακόμη· αναφέρονται στο `--report` ώστε να φανούν, αλλά και τα δύο γίνονται προσφορές.

### Νέα και αλλαγμένα φύλλα

Ρίχνεις τα καινούρια `.xls` στον φάκελο της χρονιάς ή διορθώνεις τα υπάρχοντα στη θέση τους, ξανατρέχεις το script, ξαναδιαλέγεις το αρχείο στην εφαρμογή.

Η εισαγωγή συγκρίνει κάθε προσφορά με τη βάση και τις χωρίζει σε τρία:

| | |
|---|---|
| **Νέες** | δεν υπάρχουν ακόμη — μπαίνουν πάντα |
| **Άλλαξαν στο φύλλο** | η υπογραφή περιεχομένου διαφέρει — μπαίνουν με προεπιλογή, με προειδοποίηση |
| **Ίδιες** | δεν αγγίζονται καθόλου |

Η υπογραφή περιλαμβάνει διεύθυνση, είδος, ημερομηνία, ισχύ, τρόπο πληρωμής, κατάσταση, τις γραμμές χώρων και τις σημειώσεις. Δεν περιλαμβάνει `updatedAt` ούτε ιστορικά αποστολών — αλλάζουν χωρίς να αλλάζει το φύλλο.

Όταν μια προσφορά ξαναγράφεται, οι παλιοί χώροι και σημειώσεις της γίνονται πρώτα soft-deleted: το φύλλο είναι η πηγή αλήθειας, και μια γραμμή που σβήστηκε στο Excel δεν πρέπει να επιβιώσει επειδή απλώς δεν ξαναήρθε.

Στην εφαρμογή: Ρυθμίσεις → Δεδομένα → «Εισαγωγή ιστορικού από αρχείο».

### Ξεχωριστά στα στατιστικά

Κάθε εισαγόμενη προσφορά κρατά στη στήλη `source` τη διαδρομή του φύλλου από το οποίο ήρθε· όσες γράφτηκαν μέσα στην εφαρμογή την έχουν κενή. Στη σελίδα των στατιστικών υπάρχει διακόπτης «Ιστορικό από Excel» που τις βγάζει από τους υπολογισμούς — οι παλιές επιμετρήσεις δεν αντιστοιχούν όλες σε δουλειές που έγιναν, οπότε ο τζίρος τους είναι ένδειξη και όχι απολογισμός. Η επιλογή αποθηκεύεται.

### Μελλοντικά έτη

Ο φάκελος της χρονιάς αναγνωρίζεται με `(19|20)\d{2}`, οπότε `2027`, `2028` και μετά δουλεύουν χωρίς αλλαγή. Άλλωστε ο φάκελος είναι μόνο εφεδρεία: αν το φύλλο έχει μέσα του ημερομηνία —όπως έχουν σχεδόν όλα— κερδίζει εκείνη.

| Διαφημιστικά τέλη | `ADVERTISING` | `Οφειλές/Διαφημιστικά τέλη` |
| Μισθοδοσία | `PAYROLL` ανά άτομο, `PAYROLL_BONUS` για τα δώρα | `Οφειλές/Μισθοδοσία` |

Το ΙΚΑ και το ΤΕΚΑ βγαίνουν από την ίδια ΑΠΔ και πληρώνονται μαζί, γι' αυτό μοιράζονται ομάδα· μένουν όμως δύο είδη, γιατί είναι δύο αποδεικτικά με δικό του RF το καθένα.

### Ανάγνωση παραστατικών

Τρία σκαλιά, με αυτή τη σειρά (`DocumentText`):

1. **Εξαγωγή κειμένου.** Το `DocumentBytes.hasTextLayer` κοιτάζει αν το PDF δηλώνει `/Font` — στα ωμά bytes ή μέσα σε συμπιεσμένα object streams. Αν ναι, το αρχείο αντιγράφεται στο Drive ως Google Doc και εξάγεται σε `text/plain`: τα ποσά έρχονται αυτούσια, χωρίς εικασία.
2. **ocr.space, μηχανή 3.** Για ό,τι δεν έχει κείμενο μέσα του — σαρωμένα έντυπα και στιγμιότυπα οθόνης. Η μηχανή 3 δεν παίρνει παράμετρο γλώσσας· αν αρνηθεί, δοκιμάζεται η 1 με `language=gre`. Το κλειδί ζει στις ρυθμίσεις και αδειάζει.
3. **OCR του Drive** (`files.copy` με `ocrLanguage=el`), ως δίχτυ ασφαλείας.

Έτσι δεν μπαίνει βιβλιοθήκη PDF ούτε μηχανή OCR στο apk, και η αναγνώριση ελληνικών δεν εξαρτάται από το ML Kit, που δεν τα υποστηρίζει. Το «Σημείωμα για Πληρωμή» της ΑΑΔΕ δεν έχει **ούτε έναν** χαρακτήρα μέσα του — είναι σχεδιασμένο σε καμπύλες — οπότε περνάει πάντα από το δεύτερο σκαλί.

Ο δρόμος που ακολουθήθηκε φαίνεται στον χρήστη πριν αποθηκεύσει: άλλο πράγμα ένα ποσό διαβασμένο και άλλο ένα ποσό μαντεμένο.

Ο `DebtParser` αγκυρώνει κάθε τιμή σε **ετικέτα** και όχι σε θέση: η σειρά των γραμμών αλλάζει ανάλογα με το πώς βγήκε το κείμενο, και σε κάποια έντυπα ο αριθμός τυπώνεται *πριν* από την ετικέτα του. Ένα ποσό αναγνωρίζεται από τα δύο δεκαδικά με κόμμα — αλλιώς το «Ποσό δόσης δήλωσης της 31/08/2026 30,00 €» θα διαβαζόταν ως 31 ευρώ.

Η **ταυτότητα οφειλής** τυπώνεται σε τριάδες με κενά και αποθηκεύεται ως ενιαία σειρά ψηφίων, όπως μπαίνει στην τράπεζα. Το ίδιο και τα RF.

Η **μισθοδοτική κατάσταση** είναι πίνακας σταθερών στηλών: ο εργαζόμενος ανοίγει με «α/α κωδικός ΕΠΩΝΥΜΟ ΟΝΟΜΑ …», ακολουθούν γραμμές αποδοχών που ξεκινούν με τον κωδικό τους, και κλείνει με μια γραμμή που είναι *μόνο αριθμοί* — το τελευταίο νούμερο εκείνης της γραμμής είναι το πληρωτέο του. Η γραμμή του γενικού συνόλου δεν μπερδεύεται, γιατί περιέχει και το όνομα του έργου.

Το όνομα κρατιέται πάντα ως τα **δύο πρώτα λεκτικά**, όσα κενά κι αν χωρίζουν τις στήλες: το κείμενο από OCR χάνει τη στοίχιση, και ένα όνομα που άλλαζε ανάλογα με τον τρόπο ανάγνωσης θα έφτιαχνε δύο εγγραφές για το ίδιο άτομο.

Οι κωδικοί αποδοχών γίνονται ανάλυση στην περιγραφή: `ΤΑ` τακτικές, `ΕΑ` επίδομα αδείας, `ΑΛ` άδεια ληφθείσα, `ΜΛ` άδεια μη ληφθείσα. Τα **δώρα** (`ΔΠ`, `ΔΧ`) βγαίνουν σε δική τους γραμμή, γιατί πληρώνονται χωριστά· το έντυπο δίνει ένα ενιαίο πληρωτέο, οπότε η κατανομή γίνεται **αναλογικά με τα μεικτά** — είναι εκτίμηση και διορθώνεται με το χέρι.

Ο ίδιος εργαζόμενος δύο φορές στην ίδια κατάσταση γίνεται **μία** πληρωμή με το άθροισμα. Δεν είναι μόνο ευκολία: το αναγνωριστικό βγαίνει από όνομα και περίοδο, οπότε χωρίς τη συγχώνευση η δεύτερη γραμμή θα έσβηνε την πρώτη.

Το **ευρετήριο εργαζομένων** γεμίζει μόνο του με κάθε εισαγωγή. Τα ψευδώνυμα που βάζει ο χρήστης δεν χάνονται: η καταχώρηση γίνεται με `INSERT OR IGNORE`, και ο σύνδεσμος με το τυπωμένο όνομα μένει ώστε η επόμενη κατάσταση να ταιριάξει στο ίδιο άτομο.

### Δύο δρόμοι εισαγωγής

* **Εισαγωγή αρχείου** — ο χρήστης διαλέγει PDF από τη συσκευή· ανεβαίνει **αντίγραφο** στον υποφάκελο του φορέα και μετά διαβάζεται. Δουλεύει πάντα.
* **Σάρωση Drive** — διαβάζει όσα PDF βλέπει στους φακέλους και δεν έχει ξαναδιαβάσει. Το scope `drive.file` δίνει πρόσβαση σε ό,τι έχει αγγίξει το ίδιο το app, οπότε ένα αρχείο που ανέβηκε από αλλού μπορεί να μη φαίνεται· τότε το μήνυμα στέλνει στον πρώτο δρόμο.

Τίποτα δεν αποθηκεύεται χωρίς επιβεβαίωση: ό,τι διαβάστηκε εμφανίζεται σε λίστα με checkbox και ποσά, και μένει επεξεργάσιμο μετά.

### Αναγνωριστικά και επαναλήψεις

Το id βγαίνει από το περιεχόμενο (`sha1` του είδους, της περιόδου, της ταυτότητας και του εργαζόμενου), οπότε το ίδιο παραστατικό δεν μπαίνει δεύτερη φορά. Σε επανεισαγωγή, η κατάσταση πληρωμής κρατιέται: ένα παραστατικό που ξαναδιαβάστηκε δεν σημαίνει ότι η οφειλή ξαναγεννήθηκε απλήρωτη.

Οι προθεσμίες που δεν γράφονται στο έντυπο υπολογίζονται: εισφορές και τέλη ως το τέλος του **επόμενου** μήνα από την περίοδο, μισθοδοσία μέσα στον ίδιο μήνα. Είναι εκτίμηση και αλλάζει με το χέρι.

### Ο κοινόχρηστος φάκελος

Ο `DriveWatch` συγκρίνει το περιεχόμενο των φακέλων με ό,τι έχει ήδη δει η εφαρμογή (`knownDriveIds`):

* **νέο αρχείο** → σηματάκι στο μενού και ειδοποίηση στο κινητό, με το ποιος το ανέβασε (`lastModifyingUser`)
* **αρχείο που χάθηκε** → οι οφειλές που κρέμονταν από αυτό σβήνονται (soft delete, ώστε να ταξιδέψει η διαγραφή)

Τρεις προφυλάξεις: η **πρώτη** εκτέλεση καταγράφει σιωπηλά τα πάντα ως γνωστά — αλλιώς θα φώναζε για κάθε αρχείο μηνών· μια αποτυχία ανάγνωσης φακέλου δεν μετράει ως διαγραφή· και ό,τι ανέβασε ο **ίδιος** λογαριασμός δεν ειδοποιεί τη δική του συσκευή.

Η εφαρμογή δεν τρέχει στο παρασκήνιο: ο έλεγχος γίνεται όταν ανοίγει. Μια υπηρεσία που θα ρωτούσε το Drive συνέχεια θα έτρωγε μπαταρία για κάτι που δεν είναι επείγον.

Reference implementation & έλεγχος σε πραγματικά αρχεία: `migration/parse_debts.py`.

## Σύνδεσμος πρόσκλησης

Ο διαμοιρασμός του φακέλου δίνει πρόσβαση στο Drive, αλλά η εφαρμογή του συνεργάτη δεν ξέρει *ποιο* Sheet και ποιον φάκελο να ανοίξει. Το email της πρόσκλησης περιέχει σύνδεσμο προς `docs/connect.html` με τα αναγνωριστικά ως παραμέτρους· η σελίδα προωθεί σε `prosfora://connect?…`, που το `MainActivity` διαβάζει και δείχνει διάλογο επιβεβαίωσης.

Δικό μας scheme και όχι https intent-filter: τα https links θέλουν επαλήθευση με `assetlinks.json` για να τα ανοίγει η εφαρμογή, ενώ ένα custom scheme δουλεύει αμέσως. Ο σύνδεσμος δεν είναι μυστικό και δεν δίνει καμία πρόσβαση — μεταφέρει μόνο αναγνωριστικά, τα δικαιώματα τα κρατά το Drive.
